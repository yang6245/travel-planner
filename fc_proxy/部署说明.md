# 阿里云 FC 代理部署说明（①）

## 目标
让行程小程序的「保存」动作经由国内阿里云函数计算（FC）转发到 GitHub，解决直连 GitHub API 慢的问题。**读取/轮询仍走 jsDelivr CDN，不受影响**。

## 部署步骤（约 10 分钟）

### 1. 注册并实名认证
- 打开 https://fc.console.aliyun.com ，用支付宝/淘宝账号登录
- 完成**实名认证**（个人认证即可）

### 2. 创建函数
1. 控制台左上角确认是「函数计算 3.0」（新账号默认即 3.0）
2. 左侧「函数」→「创建函数」
3. 函数类型：**Web 函数**（FC 3.0 已无独立「HTTP 函数」，Web 函数即处理 HTTP 请求）
4. 运行环境：**内置运行时 / Python 3.10**（或 3.9/3.11/3.12）
5. 函数名称：`github-proxy`（任意）
6. 代码上传方式：选「**使用示例代码**」（创建向导里没有在线编辑入口，属正常）
7. **请求处理程序（handler）**：保持默认 **`index.handler`** 即可（FC 默认代码文件是 `index.py`，我们的函数也叫 `handler`，所以 `index.handler` 最省事）
8. **最小实例数**：建议改为 `0`（无调用不计费，冷启动 1~2s 可接受）；默认 1 则常驻计费
9. 点「创建」

### 2.1 创建后替换代码（关键）
- 创建完成自动进入函数详情页 → 底部会打开 **OpenCode Server 代码编辑器**
- 左侧文件树找到 `index.py`，双击打开
- 编辑器内**清空默认 HelloWorld 代码**，粘贴 `fc_proxy/fc_proxy.py` 全文
- 请求处理程序保持 `index.handler`（与 `index.py` 对应）
- 点编辑器上方「**部署代码**」（或「保存并部署」）

> 如果你创建时把 handler 改成了 `fc_proxy.handler`，则需要额外新建 `fc_proxy.py` 文件（见下方 2.2 备选方案），或者找到「函数详情」页里的请求处理程序改回 `index.handler`。

### 3. 获取访问 URL
- 函数详情页 → 「触发器」→ 记下 **公网访问地址**（形如 `https://xxx.cn-hangzhou.fcapp.run`）
- 后面要填到页面里
- ⚠️ **触发器认证方式必须改「无需认证」**：默认是「签名认证」，浏览器/小程序直接 POST 会被 FC 拒绝。点触发器齿轮 → 认证方式 → 选「无需认证」
- 注：此地址是 **API 接口不是网页**，浏览器直接打开会下载一个 JSON 文件（或显示 401 提示），属正常现象；真正调用由小程序 POST 完成

### 4. 页面配置（以管理员身份）
1. 打开行程页面 → 点「同步设置」（编辑模式下可见）
2. 在「阿里云 FC 代理」区域粘贴上面的 URL
3. 点「保存 FC 地址」

### 5. 验证
- 正常编辑保存一次 → 状态应显示「已同步」（走 FC）
- 打开浏览器 F12 → Console 应看到 `已通过阿里云 FC 代理保存`

## 费用说明
- **3 个月试用**：新用户免费额度（15 万 CU/月）
- **之后按量**：只有「有调用的小时」才计费，每小时最低 0.01 元；**不使用时（无调用）0 元**
- 按您每年 3 次旅行的用量，年成本约 **0.3~0.5 元**
- 想完全 0 元：不旅行时可在控制台「停用函数」

## 安全说明
- GitHub Token **只从浏览器发送到 FC 函数**，不暴露在 URL 中
- FC 函数代码只做转发，**不存储 Token、不落盘**（内存中用完即弃）
- 函数未配置鉴权密钥，但攻击者没有 GitHub Token 也无法写入（GitHub 会拒绝）

## 回退
- 不想要 FC 时：页面「同步设置」→「清除」FC 地址即可，自动回退直连 GitHub
